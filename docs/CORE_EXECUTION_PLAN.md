# Core execution plan

Work proceeds in this order. Existing capture, review, settings, visual interpretation, and person-specific guidance stay in place.

1. **Qualify controllable camera changes — complete.** Focus, exposure compensation, digital zoom, and coarse white balance have apply/reset behavior and physical-device evidence. A direct-setting recommendation may combine two or three compatible axes from exposure compensation, digital zoom, and qualified white balance. Generic focus accepts any preview tap and never requires a face. ISO and shutter remain unavailable until they pass a coupled manual-exposure gate.
2. **Map comments to safe Control Intents — complete.** Convert explicit whole-frame complaints into bounded local intents. Two or three compatible direct-setting intents, with at most one exposure, one zoom, and one white-balance direction, become one recommendation and one Apply action. Clarify blur, distance, negation, same-axis conflicts, unknown clauses, named-region requests, and any compound that mixes a direct setting with focus, level, or physical movement; keep unsupported ISO/shutter/noise requests advisory.
3. **Add the strict hosted-model classifier — implementation complete; reliability measured.** The configured Alibaba Cloud model may return only one allowlisted semantic intent, a two- or three-label compatible direct-setting list, or an allowlisted clarification reason under strict schema v2. It cannot return values, coordinates, settings, commands, or prose. Android reparses, canonicalizes, capability-checks, and plans locally. In the clean run at commit `13aff93`, 9/14 cases returned the expected result within 15 seconds, three additional responses were exact but late, one disconnected, and one safely clarified instead of returning the expected darker intent. The physical Android path also tested and encrypted the configured demo key, classified one locally unknown comment, rejected an intentionally stale Apply, applied a fresh bounded `+0.7 EV` plan, and restored the camera baseline with Reset. The provider is still not a reliable dependency and remains optional and fail-closed.
4. **Test the complete comment-to-camera chain — complete.** Deterministic tests cover classifier result → local plan → one explicit Apply → fresh provenance/capability check → all setting setpoints or exact rollback → one Reset to the original baseline. The OnePlus passed the seven-test physical gate, including a compound chain that applied Zoom `1.00× → 1.25×` and white balance `Auto → Cooler` together, then restored both with one Reset.
5. **Test voice end to end — product flow complete; acoustic provider gate red.** Voice is never always-on: **Mic** starts one utterance, Android may endpoint automatically, and **Done** requests finalization. A rapid **Done** is queued until the recognizer reports ready, backgrounding cancels listening, and a 20-second app timeout returns to the typed fallback. Typed and injected voice results reach the safe intent chain. Reports `20260809-162043`, `20260809-163230`, `20260809-163717`, and the rebuilt real-UI run `20260809-170120` prove recognizer-ready → Edge playback → Edge-complete → **Done** ordering while preserving the phone's English locale. Local TTS, Edge neural TTS, and a commit-pinned human recording reached the OnePlus microphone and SODA, but all returned an empty final result followed by error 7. The acoustic on-device speech-to-text → intent → Apply gate is therefore not green on this provider.
6. **Add a capability-aware in-app guide — complete.** A small live-preview overlay opens a scrollable tutorial, gives example requests, reports direct-control support from the active camera session, distinguishes guidance from camera settings, and expands plain-language explanations of EV, focus, digital zoom, white balance/color temperature, ISO, shutter speed, level, distance, and angle. It labels ISO/shutter as unavailable in this app version rather than making an unproven phone claim, and shows only native white-balance presets actually exposed. Instrumentation covers open/close, capability variations, collapse/expand semantics, and 200% text while controls load.
7. **Run final product gates — non-acoustic local/device gates complete.** JVM passed `159/159`; API 31 and API 34 each passed `45/45`; the OnePlus passed all seven physical CameraX tests; fresh guide/compound UI inspection found no clipping; lint passed with 0 errors and 11 warnings; the configured key has zero tracked-file matches; and debug, test, minified unsigned release APK, and unsigned release-bundle builds succeed. The optional Qwen schema-v2 run is recorded above and the device's acoustic speech-to-text provider remains the red gate.

Every green milestone is committed on `codex/core-functionality`. The model/API key remains outside Git.
