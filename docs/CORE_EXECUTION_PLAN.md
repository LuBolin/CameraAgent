# Core execution plan

Work proceeds in this order. Existing capture, review, settings, visual interpretation, and person-specific guidance stay in place.

1. **Qualify controllable camera changes — complete.** Focus, exposure compensation, digital zoom, and coarse white balance have apply/reset behavior and physical-device evidence. A direct-setting recommendation may combine two or three compatible axes from exposure compensation, digital zoom, and qualified white balance. Generic focus accepts any preview tap and never requires a face. ISO and shutter remain unavailable until they pass a coupled manual-exposure gate.
2. **Map comments to safe Control Intents — complete.** Convert explicit whole-frame complaints into bounded local intents. Two or three compatible direct-setting intents, with at most one exposure, one zoom, and one white-balance direction, become one recommendation and one Apply action. Clarify blur, distance, negation, same-axis conflicts, unknown clauses, named-region requests, and any compound that mixes a direct setting with focus, level, or physical movement; keep unsupported ISO/shutter/noise requests advisory.
3. **Add the strict hosted-model planner — implementation complete.** The configured Alibaba Cloud model receives the complete request, clean reduced camera frame, and labelled grid copy, then returns one schema-v3 ordered list of up to eight allowlisted semantic adjustment, lens, focus-cell, and terminal capture actions, or an allowlisted clarification. Android rejects malformed plans and owns device-specific values, confirmation, rollback-safe execution, camera switching, focus taps, countdown, and capture. The older schema-v2 classifier measurements remain historical reliability evidence rather than the current app contract.
4. **Test the complete request-to-camera chain — complete in deterministic tests.** Tests cover model plan → local setting plan → Apply → lens rebind and approved-setting reproduction → focus-cell confirmation → countdown → capture, plus strict malformed-plan rejection and local fallback. Final-APK report `20260809-191636` remains the latest full physical CameraX gate; the schema-v3 planner change has passed JVM, lint, build, and targeted contract instrumentation on API 31, API 34, and the OnePlus.
5. **Test voice end to end — complete on the qualified target.** Voice is never always-on. On Android 13+, **Mic** starts a bounded privacy-sensitive `AudioRecord` capture in RAM; **Done** stops and releases the recorder before the finite PCM is passed through a pipe to the on-device recognizer. Rapid **Done** is queued until capture is active, backgrounding cancels the operation, audio is cleared after use, and a 20-second timeout returns to the typed fallback. Android 12/12L retain the direct on-device recognizer path. Four final OnePlus/API 35 reports (`20260809-185305`, `20260809-185406`, `20260809-190327`, and final-APK run `20260809-191527`) prove capture-ready → Edge secondary-speaker playback → Edge-complete → **Done** → on-device transcript → compatible exposure-plus-zoom plan → one Apply → EV/zoom convergence → Reset. Every run also passed a same-instance silence/no-stale-buffer/no-camera-change control. Earlier error-7 reports are retained only as provenance for the superseded recognizer-owned microphone route. Because Android providers may ignore an injected audio source, this route is qualified for the connected OnePlus/provider rather than claimed for every API 33+ phone.
6. **Add a capability-aware in-app guide — complete.** A small live-preview overlay opens a scrollable tutorial, gives example requests, reports direct-control support from the active camera session, distinguishes guidance from camera settings, and expands plain-language explanations of EV, focus, digital zoom, white balance/color temperature, ISO, shutter speed, level, distance, and angle. It labels ISO/shutter as unavailable in this app version rather than making an unproven phone claim, and shows only native white-balance presets actually exposed. Instrumentation covers open/close, capability variations, collapse/expand semantics, and 200% text while controls load.
7. **Run final product gates — complete for the target-device MVP.** JVM passed `165/165`; API 31 and API 34 each passed `45/45`; the OnePlus passed all seven physical CameraX tests, the recorder-reuse test, and 4/4 full acoustic compound runs with silence controls; fresh guide/compound UI inspection found no clipping; lint passed with 0 errors and 11 warnings; the configured key has zero tracked-file matches; and debug, test, minified unsigned release APK, and unsigned release-bundle builds succeed. The optional Qwen reliability limits are recorded above and do not gate local coaching.

Every green milestone is committed on `codex/core-functionality`. The model/API key remains outside Git.
